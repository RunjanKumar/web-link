# Food Order — Frontend Integration Guide
---

## FLOW 1 — COD (Cash on Delivery)

### Place Order
```
POST /v1/foodOrder
```
```json
{
  "hotelId": "69119400e45e0525d4403543",
  "foodItems": [
    { "foodId": "<foodId>", "quantity": 2, "price": 110 }
  ],
  "deliveryAddress": "Room 101"
}
```

**Response:**
```json
{
  "statusCode": 200,
  "data": {
    "_id": "<foodOrderId>",        ← save this
    "totalPriceAfterTax": 564,
    "status": 1
  }
}
```

> Save `data._id` as your `foodOrderId`. Order is placed as COD. Staff collects cash at delivery.

## FLOW 2 — Online Payment (Razorpay)

Same as COD but after placing the order, customer pays online.  
COD order can also switch to online payment at any time before delivery.

---

### Step 1 — Load Razorpay Script

```html
<script src="https://checkout.razorpay.com/v1/checkout.js"></script>
```

---

### Step 2 — Initiate Payment

```
POST /v1/foodOrder/initiatePayment
```
```json
{
  "foodOrderId": "<foodOrderId>"
}
```

**Response:**
```json
{
  "statusCode": 200,
  "data": {
    "razorpayOrderId": "order_SaZtZdBOHjDnMd",
    "amount": 174000,
    "razorpayKey": "rzp_test_vM1g8qOGXkztOE",
    "currency": "INR"
  }
}
```

> `amount` is in **paise** (₹1740 = 174000). Safe to call multiple times — returns same `razorpayOrderId`.

---

### Step 3 — Open Razorpay Modal

```js
const options = {
  key:         data.razorpayKey,
  amount:      data.amount,
  currency:    data.currency,
  order_id:    data.razorpayOrderId,
  name:        'Hotel Food Order',
  prefill: {
    name:    customer.name,
    contact: customer.phone,
    email:   customer.email,
  },

  // ✅ Payment SUCCESS — Razorpay sends back 3 values
  handler: async function (response) {
    await verifyPayment({
      foodOrderId,
      razorpayOrderId:   response.razorpay_order_id,
      razorpayPaymentId: response.razorpay_payment_id,
      razorpaySignature: response.razorpay_signature,
    });
  },

  // ❌ Customer closed modal without paying
  modal: {
    ondismiss: function () {
      // Order still exists as COD — do nothing or show info
      alert('Order placed as Cash on Delivery.');
    },
  },
};

const rzp = new Razorpay(options);

// ❌ Payment failed inside Razorpay (card declined, etc.)
rzp.on('payment.failed', function (response) {
  alert('Payment failed: ' + response.error.description);
  // Order still exists as COD — do not cancel it
});

rzp.open();
```

---

### Step 4 — Verify Payment

Call this from the `handler` after Razorpay returns:

```
POST /v1/foodOrder/verifyPayment
```
```json
{
  "foodOrderId":       "<foodOrderId>",
  "razorpayOrderId":   "<response.razorpay_order_id>",
  "razorpayPaymentId": "<response.razorpay_payment_id>",
  "razorpaySignature": "<response.razorpay_signature>"
}
```

**Success:**
```json
{ "statusCode": 200, "message": "Payment verified successfully. Your order is confirmed!" }
```

**Already paid (called twice — safe):**
```json
{ "statusCode": 200, "message": "Payment already verified successfully." }
```

**Failure (wrong signature):**
```json
{ "statusCode": 400, "message": "Payment verification failed: invalid signature. Please contact support." }
```

## Error Cases

| Scenario | Status | Message |
|----------|--------|---------|
| Invalid foodId | `404` | `"Food data not found"` |
| Duplicate food items | `400` | `"Duplicate food items are not allowed..."` |
| Initiate on completed order | `400` | `"Cannot initiate online payment for a completed or cancelled order."` |
| Wrong razorpayOrderId | `404` | `"Transaction not found..."` |
| Wrong signature | `400` | `"Payment verification failed: invalid signature..."` |
| Missing foodOrderId | `400` | `"foodOrderId is required"` |

---

## Important Notes

- **COD → Online switch:** Customer can call `initiatePayment` at any time while order is PENDING or IN_PROGRESS.
- **Modal dismissed:** Order stays as COD. Don't cancel it.
- **Payment failed:** Order stays as COD. Customer can retry.
- **Network error on verifyPayment:** Don't ask customer to pay again — show their `foodOrderId` and ask them to contact support.


data =>
1. Customer clicks "Pay Now"
       ↓
2. Frontend calls POST /initiatePayment  → gets { razorpayOrderId, amount, key }
       ↓
3. Frontend opens Razorpay modal with those values
       ↓
4. Customer enters card/UPI and pays
       ↓
5. Razorpay auto-calls handler(response) with:
       response.razorpay_order_id   ← same one you passed
       response.razorpay_payment_id ← NEW (e.g. pay_AbCdEf123)
       response.razorpay_signature  ← NEW (HMAC hash, generated by Razorpay)
       ↓
6. Frontend IMMEDIATELY calls POST /verifyPayment with all 4 values:
       { foodOrderId, razorpayOrderId, razorpayPaymentId, razorpaySignature }
       ↓
7. Backend verifies signature → returns 200 "Payment verified"
       ↓
8. Frontend shows "Payment Successful ✅"
